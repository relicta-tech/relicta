# Relicta 5.0

Relicta 5.0 helps teams govern releases across larger repositories, keep release history available between runs, and turn technical change summaries into customer-facing notes with their coding agent.

## What's new

### Release changed packages independently

Monorepo teams can version changed packages separately, with package-specific versions, changelogs, and tags. Release governance and approval remain repository-wide, while teams can ship one service or library without versioning every package in the repository.

### Keep release records in SQLite or PostgreSQL

Choose a local SQLite database or PostgreSQL to persist release runs and governance memory across invocations. Import existing release history and record deployment evidence alongside release decisions.

### Draft customer notes with your coding agent

Relicta provides a version recommendation and structured summary of repository changes. Your coding agent can use that evidence together with your product context to draft customer-facing notes, then save them to the release for human review. Relicta records the draft and its provenance but does not fact-check the prose; review every claim against the changes before approval. The reviewed text stays attached to the release through approval and publishing.

### Keep package metadata and release rules aligned

Relicta can update additional version files, including Gradle properties. Configured branch restrictions and freeze periods now affect release decisions, and missing required credentials or signing configuration stop the release with an actionable error.

## Upgrade to v5

### Go applications: update the module path

Relicta's Go module now uses the `/v5` path. Update imports and your `go.mod` dependency from `/v4` to `/v5`:

```bash
go get github.com/relicta-tech/relicta/v5@v5.0.0
```

Install the CLI with:

```bash
go install github.com/relicta-tech/relicta/v5/cmd/relicta@v5.0.0
```

The v4 module remains available at its existing `/v4` path.

### Configure AI note generation in `.relicta.yaml`

The `relicta notes --ai` flag has been removed. Enable provider-generated notes in configuration instead:

```yaml
ai:
  enabled: true
```

Leave `ai.enabled` false to use deterministic notes or draft them in your coding agent session.

### Review policy and report consumers

Release commands now enforce configured `workflow.allowed_branches` and `governance.freeze_periods`. Review these settings if an existing workflow starts stopping at a policy gate.

The Article 12 supporting-evidence export renamed timestamp fields to `releaseProcessStartedAt` and `releaseRecordedAt`, and replaced `auditChainIntegrityVerified` with `auditChainIntegrityStatus`. Update consumers of the previous JSON or CSV field names. The export does not check audit-chain integrity; use `relicta audit verify` for that check. These records describe Relicta release governance; they do not record each AI system use or establish regulatory compliance.
